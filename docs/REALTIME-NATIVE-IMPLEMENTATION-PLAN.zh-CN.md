# 原生实时读取 API 修改计划（单点与批量一起交付）

## 目标与现有依据

在现有 dcs-service 中同时新增单点、批量在线参数查询，使用已验证的 DeltaV 原生调用链，保持只读。

现场已验证：native-v4 对 `SY-218/AI1/PV.CV` 经实际模块对象的同步读取入口返回状态 0，成功转换为文本 `512.694`。该结果证明当前版本的原生调用路径可用，但尚未完成画面对照、原生类型映射、源时间戳/质量和长期运行稳定性验证。

现有应用为 Windows 7 / .NET Framework 3.5 / x86，自建 HTTP 服务器已支持请求体读取，无需更换 HTTP 框架。现有 Historian 和 Event Journal 各有独立并发门控；新增实时读取使用自己的门控与错误分类。

## 1. 实现架构

采用“现有 HTTP 服务 + 独立 x86 原生读取 Worker”：

```text
HTTP 单点/批量请求
  -> 参数校验与实时读取并发门控
  -> RealtimeProvider
  -> 一个独立 Worker 进程处理本次请求
       初始化 DeltaV 一次
       顺序读取本次一个或多个参数
       返回结构化结果并退出
  -> HTTP JSON 响应
```

- 单点和批量复用同一读取引擎；单点是只有一个参数的请求。
- 每次批量仅初始化一次原生运行时，不为每个点新建进程。
- 主服务不加载新增的原生运行时。原生崩溃、挂起或异常由本次 Worker 承担。
- 不启用常驻 Worker 池。当前尚未确认模块会话及转换文本的完整释放规则，优先通过有数量上限、时间上限的 Worker 生命周期回收资源。
- 能确认释放方式的本地对象正常清理；尚未确认归属的厂商分配结果保留至本次 Worker 退出，不能换用猜测的释放器。长时间不退出的 Worker 不符合这一设计。
- 参数以结构化输入传给 Worker，不经 shell 拼接执行；stdout 保持结果协议，stderr 记录诊断。结果需与请求逐项对应，检测不完整、重复或意外输出。
- 当前宿主仍需处于可用的 DeltaV 登录/运行环境。交互用户测试成功不代表 Windows 服务账户一定可用，部署验收需覆盖实际运行账户。

## 2. API 约定

单点：

```http
GET /api/v1/realtime?tag=SY-218%2FAI1%2FPV.CV
```

批量（只读操作，POST 用于承载参数列表）：

```http
POST /api/v1/realtime/batch
Content-Type: application/json

{"tags":["SY-218/AI1/PV.CV","另一个完整参数路径"]}
```

第一版仅接受完整原生参数路径。不通过 Historian `/tag` 验证，不猜测模块的 AI1/PID1 等功能块。

单点与每一条批量结果使用同样的数据结构，包含：

- tag、ok；
- value、valueType、nativeDataType；
- 必要时保留原生格式化文本 valueText；
- observedAt（读取时间）、sourceTimeZone；
- sourceTimestamp、quality（未实际取得时明确为 null）；
- 失败时的 error.code、message、stage、nativeStatus、nativeStatusName。

原生类型名、数字精度与转换规则先核实，再实现。不能仅将格式化文本解析为数字后声称保留原始精度。不能将类型码 8 直接当成字符串，也不能对所有点强行使用某种数值类型。

批量约定：

- 保留输入顺序，每个输入位置都有对应结果；重复路径的处理保持明确，第一版按输入位置返回，不静默删项。
- 一个参数查不到或返回可恢复原生错误时，记录该点失败并继续后续点。
- 进程崩溃、超时、协议损坏属于请求级故障。未完成或未验证的点不能伪装为成功；第一版可整体返回请求级错误，不承诺回收崩溃前的部分数据。
- 批量顺序采样，各点记录各自读取时间，不承诺同时刻快照。
- 完整执行的批量返回 HTTP 200，并给出总数、成功数、失败数和逐项结果；顶层 ok 仅在全部成功时为 true，并明确 complete=true。部分或全部点失败仍可与请求级故障区分。
- 非法请求用 400；原生环境不可用/资源繁忙用 503；Worker 超时用 504。补充 HTTP 状态文本与相应错误映射。

## 3. 修改位置

### 原生读取层与 Worker

新增 `src/DcsNativeReadWorker/`，将 native-v4 的有效调用链整理为受控的单点/批量读取组件，包含 ABI/版本校验、实际对象虚函数分派、原生文本转换、类型处理及错误解码。

配置中的 DLL 目录与受支持 ABI/二进制版本必须匹配；验证失败时明确拒绝原生调用。不提供“忽略版本检查后继续调用”的开关。

### 服务 Provider 与数据模型

新增 `src/DcsDataService/DeltaV/Realtime/` 和实时读取数据模型。Provider 管理 Worker 启动、双通道输出读取、整体期限、退出码、协议校验与进程回收。服务退出时结束本服务启动且尚未完成的 Worker，不能误杀其他 DCS 进程。

### 路由和 HTTP 错误

新增 RealtimeHandler / RealtimeBatchHandler，并接入 Router、HandlerContext、Program。

ApiServer 增加实时读取专用异常映射，避免被现有“FileNotFound -> Historian 不可用”或“InvalidOperation -> Event 不可用”的通用规则误分类。

### 配置和信息接口

扩展 ServiceConfig、IniConfigLoader、config.example.ini：

- Realtime.Enabled；
- DeltaVBinDirectory、WorkerPath；
- MaxBatchTags、单条路径长度限制；
- MaxConcurrent、排队等待期限、Worker 整体期限；
- 用于现场探测的可选 TestTag。

旧配置缺少新节时仍可启动，实时功能默认不启用。启用后做配置校验；运行时故障按实时接口错误返回。历史与事件不因实时 Worker 的故障而退出。

扩展 info 与可选 realtime probe，报告“配置启用/文件校验/实际读取”的区别。普通 health 不执行 DCS 参数读取。

### 构建、CLI 和文档

构建脚本生成并部署主服务及 Worker，维持 .NET 3.5 / x86，不自动覆盖 DeltaV 安装目录里的厂商文件。

扩展项目内 dcs-data CLI：新增 `realtime <完整路径>` 和 `realtime-batch <路径...>`，使用统一错误和 JSON 结果；更新技能与 API 文档。安装到用户技能目录的版本在代码验证后同步，保留既有修改。

## 4. 验证计划

本地无需 DCS 的验证：

- 单点/批量请求解析、非法列表、数量上限、返回顺序、重复路径；
- 类型与精度转换、空值及未知类型；
- 混合成功失败、全点失败、原生错误映射；
- Worker 超时、崩溃、空结果、协议不完整、大量 stderr，保证无死锁与进程残留；
- 并发门控和过载行为；
- 旧配置兼容，现有历史/事件测试与 HTTP 检查继续通过。

现场验收脚本与源码一起交付，覆盖：

1. 已确认路径 `SY-218/AI1/PV.CV` 的 API 结果与同期 WatchIt/画面对照；
2. 一个明确未配置历史采集的点的读取；
3. 包含有效点和无效点的批量查询，验证失败不影响同批其他点；
4. 实际存在的不同数据类型，核对返回类型与精度；
5. 连续请求和并发请求，观察主服务与 Worker 的内存、句柄、延迟和退出情况；
6. 实际部署账户、服务启停，以及历史与事件接口并行可用性。

超时、批量上限和并发初始值采用保守设置，依据现场数据确认。未经验证不做刷新率或“任意点均可读”的承诺。

## 5. 实施顺序与交付

1. 固定 API/Worker 协议与批量结果语义。
2. 整理原生读取引擎，完成一个 Worker 内的单点/批量处理。
3. 接入 Provider、路由、配置、错误分类及服务启停管理。
4. 补充 CLI、文档、构建与离线测试。
5. 打包现场验收脚本，完成单点、批量、故障及连续运行验证。

以上为一项完整修改，单点和批量一起交付。当前阶段仅制定计划，尚未将原生调用接入主服务或修改 API 行为。
